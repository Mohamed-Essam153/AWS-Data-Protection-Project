# Data loss prevention plan

Deliverable 18. Owner: Ahmed Ali

There's no single DLP product on AWS. DLP here is a set of controls that prevent, detect and respond, and every one of them is already somewhere in this repo.

## 1. What we protect

- Stores: the data bucket, DynamoDB table, RDS (optional), Secrets Manager, Parameter Store
- Levels: [data-classification.md](../week-1-s3/data-classification.md)
- Where sensitive data actually is: [Macie report](macie-report.md)

## 2. How data could leak

| Channel | Example |
|---|---|
| Public bucket | Block Public Access switched off by mistake |
| Over-broad access | `Principal: *` allow, a role with `s3:*` on everything |
| Shared links | a presigned URL valid for a week, forwarded outside |
| Stolen credentials | a phished console login, leaked access keys |
| The API itself | an endpoint returning whole customer records |
| Logs | a Lambda printing request bodies |
| Source control | keys or passwords committed to GitHub |
| Wrong label | card numbers in an "internal" export |

## 4. Detect

| Tool | Catches |
|---|---|
| Macie | sensitive data in the wrong place |
| GuardDuty | unusual or malicious access to S3 |
| IAM Access Analyzer | anything shared outside the account |
| CloudTrail + EventBridge | key disabled, key policy changed, and so on, by email |

## 5. Respond

**Macie finds sensitive data in the wrong place**
1. Move it to the right prefix and re-tag it (`remediate-misclassified.sh`).
2. Check access logs for who read it meanwhile.
3. Tell the data owner, log it in the risk register.

**GuardDuty reports possible exfiltration**
1. Revoke active sessions in Identity Center and disable the credentials involved.
2. Use CloudTrail and S3 access logs to work out exactly what was read.
3. Contain: a temporary deny in the bucket policy, or restrict the key policy.
4. Decide on notification: GDPR Art. 33 (72 hours to the authority), HIPAA breach notification, the PCI incident procedure.

## 6. Measure

- Sensitive objects outside their approved prefix (target: 0)
- Time from Macie or GuardDuty finding to fix
- Active Access Analyzer findings (target: 0)
- This plan reviewed every quarter
